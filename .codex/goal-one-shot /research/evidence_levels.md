# Evidence Levels

## Strong enough for product architecture

These are well-established as useful engineering patterns, even if the brain analogy is simplified:

- working memory as active task state;
- event bus or blackboard as global workspace;
- episodic memory as indexed run traces;
- semantic memory as stable facts/preferences;
- procedural memory as skills/playbooks;
- executive controller as planner/supervisor;
- attention as context selection;
- permission gating as inhibitory control;
- verification loop as prediction error handling;
- metacognition as confidence/risk/uncertainty monitoring.

## Useful but should be framed carefully

These can inspire design, but should not be overclaimed:

- basal ganglia as action-selection scoring;
- active inference as observe/predict/act loop;
- reinforcement learning as feedback-based preference/skill improvement;
- emotion/motivation as urgency/priority scoring.

## Avoid as public claims

Do not market CodePawl as:

- conscious;
- biologically equivalent to the brain;
- AGI;
- fully autonomous;
- capable of human judgment;
- safe without supervision.

## Research-to-MVP selection

For v1, implement only:

1. working memory;
2. global workspace/event bus;
3. executive controller;
4. semantic, episodic, procedural memory;
5. attention router;
6. permission gate;
7. verification/prediction-error loop;
8. feedback-to-skill loop;
9. evidence replay;
10. cost ledger.

This is enough to make CodePawl meaningfully brain-inspired without becoming speculative.
