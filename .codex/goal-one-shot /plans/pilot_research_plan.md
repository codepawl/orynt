# Pilot Research Plan

## Goal

Find the urgent workflows where a teachable computer-use agent provides enough value to justify subscription pricing.

## Pilot size

Start with 10–30 users.

## Target users

- Solo founders.
- AI engineers.
- Technical operators.
- Agencies with repetitive workflows.
- Power users who already use AI tools.

## Data to collect

For each run:
- task type;
- success/failure;
- duration;
- user intervention count;
- approval count;
- correction count;
- cost;
- retry count;
- memory retrieval usefulness;
- whether a reusable skill was created;
- whether user would pay for this workflow.

## Interview questions

1. What computer task do you postpone because it is boring but requires judgment?
2. What task do you repeat weekly or daily across browser/files/apps?
3. What would you delegate to an AI if you could approve every risky step?
4. What would you never allow an AI to do?
5. Which tasks require your personal preferences or past context?
6. What evidence would make you trust the agent?
7. What mistake would make you cancel immediately?
8. Would you prefer BYOK or managed AI credits?
9. What is the highest monthly price you would pay if this handled one painful workflow reliably?
10. Which workflow should CodePawl learn first?

## Success criteria

- 3 repeated workflows appear across multiple users.
- Users trust the permission/replay model.
- At least 30% of pilot users reuse one saved skill.
- p90 managed cost fits planned pricing.
- Users can describe the product in one sentence.

## Pricing learning

Do not finalize managed quotas until at least 100 real runs are measured.

Use:
- p50 cost for expected margin;
- p90 cost for quota design;
- p99 cost for abuse protection;
- user willingness-to-pay for packaging.
