# Monetization and Pricing

Generated: 2026-06-24

## Principle

CodePawl MVP is a closed-source commercial desktop product. Keep the local alpha usable without a production backend, but do not position the MVP as an open-core framework.

## MVP model

### Free Trial

- Desktop app download.
- Browser surface only.
- Limited controlled browser runs.
- Local traces.
- Bring-your-own model API key.
- Trial/billing UI placeholder in P0.
- Offline-first alpha mode; account-gated trial can be added later.

### Pro

- Advanced trace search.
- Token analytics.
- Multi-provider routing profiles.
- Skill templates.
- Export packs.
- Priority updates.

### Team

- Shared workspaces.
- Shared skills.
- Team policy packs.
- Audit logs.
- Cloud sync.
- Role-based approvals.

### Enterprise later

- SSO.
- Centralized policy.
- Private deployment.
- Custom surface adapters.
- Security review support.
- Data retention controls.

## Monetization wedge

The wedge is not charging for model tokens. The wedge is reducing wasted model tokens and failures.

Pricing should be framed around:

- saved time
- saved token cost
- lower debugging time
- repeatable workflow automation
- safety/audit controls

## Early revenue option

Offer a “founder engineering package”:

- custom workflow setup
- private beta access
- direct support
- lifetime discount

## Do not monetize early

- Basic safety approvals.
- Local trace export.
- Core browser adapter.
- BYOK model support.

These are core trust features.

## Backend rule

Do not block the first local MVP on account, license, or payment infrastructure. Treat billing and trial state as configurable placeholders until the runtime proves value.
