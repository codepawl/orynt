# Accessibility and Usability

Generated: 2026-06-24

## Product accessibility

CodePawl itself should be accessible. This also improves quality because the product depends on UI semantics.

## Requirements

- Keyboard navigable main UI.
- Visible focus states.
- Good contrast in glass UI.
- Do not use blur/transparency in a way that destroys readability.
- Use semantic buttons, tabs, dialogs, and forms.
- Approval cards must be screen-reader understandable.

## Usability principles

- Never hide risk.
- Show current run state clearly.
- Make stop/pause easy.
- Make trace understandable.
- Keep setup minimal.
- Do not require terminal for normal usage after install.

## Onboarding

First run should guide user through:

1. Create workspace.
2. Add model provider or local model.
3. Launch browser.
4. Run sample task.
5. Inspect trace.
6. Save skill.

## Done when

A technical user can complete the first demo without reading code.
